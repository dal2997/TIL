## ✅ Today

### 1. Supabase 기반 수집 시스템 구조 설계·구현
- 로컬스토리지 MVP → **로그인 기반 DB 구조로 전환**
- 핵심 개념 정리
  - **auth.users** : 사용자 단위 데이터 분리
  - **collection 테이블** : user_id 기준으로 개인 수집 데이터 저장
  - 다른 유저의 팬페이지도 **읽기 전용으로 조회 가능**한 구조 구상
- CRUD 흐름 명확화
  - fetchCollection / insert / update / delete 역할 분리
  - 프론트(View) ↔ 서비스 레이어 ↔ Supabase 책임 분리

### 2. Storage (이미지 업로드) 정책 이해
- Supabase storage bucket 구조 이해
  - bucket 단위 접근 제어
  - anon 공개 정책은 **임시 개발용**
- `storage.objects` 정책이 실제로 **업로드/조회/수정/삭제 권한을 결정**한다는 점 체감
- “지금은 열어두되, 나중에 auth 붙이면 닫는다”는 전략 명확화

### 3. UI 상태 꼬임 이슈 분석

### 4. 서비스 확장 방향 기획
- 모몽가 팬페이지 → **캐릭터 수집 위키형 서비스**로 확장 구상
- 핵심 방향
  - 모든 캐릭터 수집 가능
  - 운영자 검증 후 공개 (위키 + 큐레이션 구조)
- “팬페이지”가 아니라 **데이터 구조 중심 서비스**로 사고 전환
