# TIL - 251231

## 오늘 한 것

### **1) Git의 역할과 협업에서의 중요성 이해**
- Git은 단순한 백업이 아니라 **변경 이력 관리 + 협업을 가능하게 하는 도구**
- 누가, 언제, 왜 바꿨는지를 기록으로 남기는 것이 핵심 가치

### **2) Git 기본 흐름 실습 (add → commit → push)**
- `git add` → 스테이징
- `git commit` → 작업 단위 기록
- `git push` → 원격 저장소 반영
- 커밋 메시지 규칙 실습:
  - `conf: Create .gitignore`
  - `docs: Create README.md`

### **3) .gitignore의 필요성과 실제 사용**
- API Key, pem 파일, credentials 등 민감 정보는 절대 커밋되면 안 됨
- `.gitignore`를 통해 추적 대상에서 제외
- gitignore는 **프로젝트 시작 시 가장 먼저 작성**하는 게 안전

### **4) Branch 개념과 브랜치 기반 작업**
- 브랜치는 기능/작업 단위로 나누기 위한 독립 공간
- main 브랜치는 항상 안정적인 상태 유지
- `git branch fb`
- `git switch fb`

### **5) -u 옵션과 원격 브랜치 바인딩 이해**
- `git push -u origin fb`
- 처음 한 번만 `-u`를 붙여 로컬 브랜치와 원격 브랜치 연결
- 이후에는 `git push`만으로 동일 브랜치에 반영 가능

### **6) Issue 기반 개발 흐름 실습**
- 기능 구현 전 Issue 작성
- Description / Tasks / References 구조로 명확히 정리
- FizzBuzz 구현 실습:
  - 조건문 + 반복문으로 1~15 출력
- 커밋/PR에서 `resolve #1` 사용 → merge 시 이슈 자동 종료

### **7) GitHub 협업/관리 기능 이해**
- **Issue**: 할 일, 버그, 질문 관리
- **Labels**: 이슈 분류 및 가시성 향상 (예: `enhancement`)
- **Milestone**: 스프린트/주기 단위 목표 관리
- **Projects(Kanban)**: 이슈/PR 흐름 관리 (관리자 중심 운영)
- **Wiki**: 내부 문서/지식 공유용
- **Organization**:
  - 팀 단위 공간 생성
  - People 탭에서 멤버 초대
  - Organization 소유 레포 생성

### **8) Issue Template 설정과 활용**
- Settings → Features → Issues → Templates
- 공통 이슈 양식으로 협업 품질 통일
- 수업에서 사용한 템플릿 구조:
  - Description
  - Tasks
  - References

### **9) Pull / fetch / merge와 PR 충돌 해결**
- `git pull`이 항상 안전하지는 않음
- 안정적인 방식:
  - `git fetch origin main`
  - `git merge FETCH_HEAD`
- PR 충돌 발생 시:
  - 원격에서 해결 불가
  - 로컬에서 충돌 파일 직접 수정 후 add/commit/push
  - 해결되면 PR이 초록색으로 변경되고 merge 가능

### **10) Stash, restore, amend로 작업 관리**
- 커밋하지 않은 변경사항은 브랜치를 이동해도 따라다님
- `git stash`로 임시 보관
- `git stash pop`으로 복구
- `git restore`로 작업 내용 되돌리기
- `git commit --amend`로 커밋 재작성
  - 커밋 ID가 바뀌는 점 주의

### **11) Reset vs Revert 차이 이해**
- **reset**:
  - 커밋 자체를 삭제
  - 히스토리를 망가뜨릴 수 있어 위험
  - 보안 사고(API key 유출) 외에는 사용 지양
- **revert**:
  - 되돌리는 커밋을 새로 생성
  - 협업 환경에서 안전한 방식

### **12) Fork + upstream 협업 구조 실습**
- 협업 시 직접 push보다 **fork 기반 작업이 안전**
- fork 후 작업 → PR 생성
- 원본 레포는 `upstream`, 내 fork는 `origin`
- PR 완료 후 최신 반영:
  - `git fetch upstream main`
  - `git merge FETCH_HEAD`

### **13) remote 꼬임 경험과 안전 루틴 정리**
- 한 폴더에서 remote만 바꿔 다른 레포를 섞으면 히스토리가 꼬임
- 안전 루틴:
  - 작업 전 상태 확인
  - 필요 시 `reset --hard` + `clean -fd`로 정리
- 이후 항상:
  - 최신화 → 기능 브랜치 → 작업 → PR 순서 유지

### **14) 공동작업 표준 흐름 정리**
- 작업 시작 전:
  - `git switch main`
  - `git pull --ff-only`
- 기능 개발:
  - `git switch -c feature/random`
  - add / commit / push
