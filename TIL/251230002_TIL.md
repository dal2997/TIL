rm = 파일/폴더 삭제 명령
-r = recursive(재귀): 폴더 안의 내용까지 전부 내려가며 삭제
-f = force(강제): 확인 질문 안 하고, 없는 파일 오류도 무시하고 그냥 진행
즉 -rf는 “폴더째로, 묻지도 따지지도 말고 싹 지워라” 조합이라 실수하면 큰일 나기 쉬워.
안전하게 하려면 보통 먼저 확인:
ls second-repo-copy/ (무슨 파일인지 보기)

git fetch origin main
git merge FETCH_HEAD
왜 fetch + merge FETCH_HEAD를 쓰냐?
1) git fetch origin main
원격 origin/main의 최신 커밋을 다운로드만 해.
내 로컬 브랜치(main이든 fb든) 내용은 아직 안 바뀜.
2) git merge FETCH_HEAD
방금 fetch로 가져온 “그 최신 커밋”을 현재 내가 서 있는 브랜치에 머지해.
FETCH_HEAD는 “방금 fetch한 대상(여기서는 origin/main)”을 가리키는 임시 포인터라고 보면 됨.
즉, 이 두 줄은 합쳐서 말하면:
“원격 main 최신을 가져와서, 지금 내가 있는 브랜치에 그걸 머지해라.”

언제 이게 필요하냐?
PR이 아니라 로컬에서 직접 병합할 때
“내 브랜치가 오래돼서(main이 최신인데 나는 옛날 main 기반으로 작업함)” → 최신 main을 내 브랜치에 먼저 반영해서 충돌을 미리 해결하려고
혹은 PR 머지 대신 내가 로컬에서 merge 커밋 만들고 push하려고

예: fb에서 작업 중인데, 그 사이 main이 바뀌었으면
git checkout fb
git fetch origin main
git merge FETCH_HEAD   # == git merge origin/main
