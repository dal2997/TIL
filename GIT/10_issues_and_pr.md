# 🧾 Issue → PR 흐름 (수업 실전)

## ✅ Issue 작성 추천 구조
- Description
- Tasks
- References

체크박스 예시:
- [ ] fizz 구현
- [ ] buzz 구현
- [ ] fizzbuzz 구현

---

## 🔥 PR/커밋에서 이슈 자동 닫기
- `resolve #1`
- `fix #1`
- `close #1`

merge 되면 이슈가 자동 종료됨(추적/자동화에 유리)

---

## PR 기본 흐름
1) 브랜치 생성  
2) 커밋  
3) push  
4) PR 생성  
5) 리뷰/수정  
6) merge  
7) 브랜치 삭제  

## GitHub Flow와 Pull Request

- main 브랜치는 항상 배포 가능한 상태 유지
- 기능 개발은 feature 브랜치에서 진행
- PR(Pull Request)로 리뷰 + CI 통과 후 main merge

### 기본 흐름
1. feature 브랜치 생성
2. 커밋
3. PR 생성
4. 리뷰 및 CI 통과
5. main merge
